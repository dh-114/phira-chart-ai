# AI 制作 Phira 谱面的完整流程

> 本文是插件里 AI 的「作业指导书」：每一步说明**做什么、用什么工具、验收标准、常见返工点**。
> 工具名对应本插件注册的 `phira_*` 工具；未实现的（MIDI/音频/生成器）标了 🚧。

---

## 阶段 0 · 准备（人机对齐）

| 项 | 说明 |
|---|---|
| 素材 | 音频（mp3/ogg）、曲绘（png/jpg）、曲名/曲师/画师 |
| BPM | 从音频分析或曲师信息得到；多 BPM 要记下变速点 |
| Offset | 音乐第 0 拍距音频开头的毫秒数（RPE `META.offset`） |
| 难度目标 | 先定定数（如 13.5），它决定密度、手指数、判定线动效强度 |

**验收**：`chart.json` 的 `BPMList` 能在预览里对上鼓点；`info.yml` 的 `offset` 与 `META.offset` 不冲突。

---

## 阶段 1 · 听曲与分段（决定结构）

1. 🚧 `phira_audio_analyze`：输出 BPM、节拍网格、能量包络、onset 密度、段落切点。
2. 人工/AI 一起划段落：`前奏 → A 段 → B 段 → 副歌 → 间奏 → 副歌2 → 尾奏`。
3. 标出：**可以留白的段落**（休息）、**需要爆发的段落**（判定线演出）、**旋律稀疏段**（少音符装饰）。

**验收**：每个段落有明确的起止拍数（如 A 段 32 拍），后续所有编排都按段落对齐。

---

## 阶段 2 · 定视觉语言（决定"这谱长什么样"）

参考谱面实测：一条线做主体、另 1–2 条线做演出就够。

| 选择 | 说明 |
|---|---|
| 主体线位置 | y=0（标准）/ y=±200（上下） |
| 是否垂直 | 否 / 左侧 rot=90 / 右侧 rot=-90 |
| 是否四面 | 仅关键段落用（如副歌），例：`54712` 四角布局 |
| 是否扫线 | 段落过渡时扫一次（1–3s 扫过全屏） |
| 色调 | 用 `colorEvents` 给段落换色（如主歌蓝、副歌红） |
| 倾角 | IN 难度标配 `inclineEvents`（0–30 度足够） |

**验收**：能一句话描述"这谱的视觉主线"（例：中线 + 副歌扫线 + 蓝色调）。

---

## 阶段 3 · 搭时间轴骨架（空谱 + BPM）

1. `phira_chart_init`：建目录、`chart.json`、`info.yml`。
2. 写入 `BPMList`（多段变速要按 `[a,b,c]` 拍数精确落点）。
3. 写第一条判定线的 `alphaEvents`：**全程覆盖**，避免空隙导致线"消失"（RPE 空隙按插值处理）。
4. 谱面开头 0–3s 加水印文字线（AI 标识）。

**验收**：`phira_preview_frame` 在 0/10/30/60s 各出一帧，判定线位置正确、无异常消失。

---

## 阶段 4 · 音符编排（主体工作量）

### 4.1 先铺"骨架流"
- 主歌：Tap 单点流（1/8 或 1/4 拍），x 在 ±300 内。
- 副歌：加入双押、楼梯、交互。
- 每 8–16 拍换一次手法，避免重复疲劳。

### 4.2 再插"色彩音符"
| 手法 | 规则 |
|---|---|
| Drag（蓝键） | 用于垫音/装饰，不需要点；**不要和 Tap 混在同轨** |
| Flick（粉键） | 点缀，单段 ≤ 4–6 个 |
| Hold（长条） | 0.3–0.8s 舒适；**同轨长条内只放 Tap/Flick** |
| 假音符 | 装饰必须 `isFake=1`，否则会被判定 |

### 4.3 用配方批量生成
`phira_chart_apply_pattern`（🚧 待实现）支持：
`stairs / trill / jack / chord / hold-inner / sweep / vertical / four-side / freeze`

**验收**：峰值同刻 ≤ 难度允许（<15 定数 ≤2 指）、无同刻点击类横向重叠（间距 ≥ 220px）、开局留白 ≥ 2s。

---

## 阶段 5 · 判定线演出（决定"高级感"）

原则：**动效跟着音乐，不跟着屏幕**。

| 时机 | 做法 |
|---|---|
| 段落过渡 | 扫线（1–3s，−675→675）或旋转 180° |
| 鼓点重拍 | alpha 脉冲（255→120→255）或小幅缩放 |
| 副歌 | 倾角 + 缩放 + 染色组合 |
| 休息段 | 线淡出、位置缓慢漂移 |
| 特殊段落 | 垂直判定 / 四面判定 / 屏外线（围屏） |

红线：
- 判定线瞬移（同刻大位移）不要发生在音符落点附近；
- `alpha<0` 会连音符一起隐藏，非必要不用；
- 文字事件线不放音符；
- 每条线只做 1–2 种变化，别堆。

**验收**：`phira_preview_strip` 抽 6–8 帧看：线是否清晰、音符是否被遮挡、动效是否盖住判定区。

---

## 阶段 6 · 打磨（节奏与呼吸）

1. 每个高潮后留 0.5–1s 空档（参考谱面实测普遍有 0.5–3s 休息）。
2. 长条段与密集段交替，避免连续 20 秒高压。
3. 结尾：判定线淡出 + 最后一个长条/单点。
4. 物量对齐：定数 13 左右 ≈ 4–5 音符/s；15 ≈ 6–8/s；16+ 靠多指或耐力。

---

## 阶段 7 · 校验（必须 0 error）

`phira_validate`：
- **error** 必须清零：NaN 时间、father 成环、缺字段、alpha 越界、出界真音符。
- **warning** 逐条判断：碰撞、贴边、判定线极速、长条内嵌类型、开局无准备。
- **info** 可忽略：超短长条、numOfNotes 不一致。

---

## 阶段 8 · 预览抽帧自检

1. `phira_preview_frame`：在关键节点（段落开始、判定线演出、长条段、结尾）各出一帧。
2. `phira_preview_strip`：连续 6–8 帧看动势。
3. 检查清单：
   - 音符是否压线/出屏；
   - 判定线是否挡住音符（尤其旋转后）；
   - Hold 体是否穿过其它音符；
   - 同一轨道是否有两个音符同时到达。

---

## 阶段 9 · 难度与可玩性校准

`phira_analyze`：
- 定数预测 vs 目标：偏差 > 0.8 就调整密度/手指数。
- 手指数检查：按难度档（默认 <15 限 2 指，15–16 限 3 指，17+ 放开）。
- 可玩性 10 项逐条过。

---

## 阶段 10 · 导出与声明

1. `info.yml`：`charter: "xxx (AI)"`、`tags: [AI生成]`、`intro` 说明。
2. 谱面内 0–3s 水印。
3. 打包：`info.yml` + `chart.json` + 音频 + 曲绘（zip 根目录直接放文件）。
4. 禁止：图片纹理、GIF、paint 事件。

---

## 附：一个 12 秒片段的示例时间表（180 BPM，1 拍 = 0.333s）

| 时间 | 内容 | 手法 |
|---|---|---|
| 0–2s | 水印 + 判定线淡入 | 文字线 + alpha |
| 2–4s | 留白 | 无音符 |
| 4–8s | Tap 单点流（1/4 拍） | stairs（x 从 −300 到 300） |
| 8–9s | 双押 ×4 | chord-2，间距 400 |
| 9–10.5s | 长条 ×2 + 内嵌 Tap | hold-inner |
| 10.5–11.5s | 判定线横扫 + 粉键点缀 | sweep + flick |
| 11.5–12s | 收尾单点 | tap |

> 全流程可循环：每段都走「编排 → 校验 → 抽帧 → 校准」，AI 不需要一次写对，靠工具闭环迭代。
